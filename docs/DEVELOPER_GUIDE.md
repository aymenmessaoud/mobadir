# دليل المعايير البرمجية والهندسة النظيفة — منصة مُبادِر (Mobadir)
> **دليل مهني للمطورين المستقبليين:** توثيق قواعد كتابة الكود، الهيكلة المعمارية، معايير التوثيق بالتعليقات (DocBlocks)، وبروتوكولات التوسع الآمن.

---

## 1. الفلسفة المعمارية للمشروع (Architectural Philosophy)

1. **الاستقلالية والاعتمادية الذاتية (Zero-Dependency & No Build System):**
   - لا نعتمد على أدوات بناء معقدة مثل `npm`, `webpack`, `vite` أو حزم ثقيلة قد تنكسر بمرور السنين.
   - الكود يعتمد على Vanilla PHP و CSS نقي حديث يدعم المتغيرات والشبكات (CSS Grid & Flexbox) و Vanilla JS خفيف.
   - هذا يضمن أن المشروع يعمل على أي خادم ويب (Apache, LiteSpeed, Nginx) وعلى أي إصدار PHP حديث من 7.4 وحتى 8.3+ دون حاجة لأي تثبيت حزم أو Composer.

2. **التنظيم الفصلي للمسؤوليات (Separation of Concerns):**
   - **`config/`:** الإعدادات العامة والاتصال بالخادم.
   - **`includes/`:** منطق الأعمال والوظائف المساعدة والتحقق (Business Logic).
   - **`pages/` & `club/` & `admin/`:** قوالب العرض البصري (Presentation Layer / Views).
   - **`index.php`:** متحكم الدخول وتوجيه الإجراءات (Controller / Router).

---

## 2. معايير كتابة التعليقات وتوثيق الأكواد (Code Documentation Standards)

لكي يستطيع أي مبرمج مستقبلي قراءة الكود وإصلاحه بسلاسة، نلتزم بالمعايير التالية في جميع الملفات:

### أ. ترويسة الملف (File Header DocBlock)
كل ملف PHP يجب أن يبدأ بترويسة توضح وظيفته، سياقه، وموقعه:
```php
<?php
/**
 * [اسم المكون / الصفحة] — Mobadir (مُبادِر)
 * 
 * الوصف: [شرح مختصر لما يفعله هذا الملف ودوره في النظام]
 * المدخلات المتوقعة: [مثل $_GET['id'] أو معايير الجلسة]
 * الصلاحيات المطلوبة: [الضيوف / المتطوعون / الأندية / الإدارة]
 */
```

### ب. توثيق الدوال البرمجية (Function DocBlocks)
كل دالة في `includes/` يجب أن تحتوي على DocBlock يوضح:
- وصف وظيفة الدالة
- معاملات الدخل (`@param`) وأنواعها
- قيمة الخرج (`@return`) ونوعها
- الاستثناءات المحتملة (`@throws`) إن وجدت

مثال من `includes/helpers.php`:
```php
/**
 * احتساب الرتبة والشارة الوطنية للمتطوع بناءً على عدد الساعات المعتمدة
 *
 * @param int $hours إجمالي الساعات المعتمدة رسميّاً في قاعدة البيانات
 * @return array مصفوفة تحتوي على: (level, title, emoji, badge_color, description, next_target, progress)
 */
function calculate_volunteer_badge(int $hours): array {
    // ...
}
```

### ج. فواصل الأقسام المنطقية (Section Dividers)
استخدام فواصل أفقية معيارية لتقسيم الكود الطويل إلى كتل مفهومة:
```php
// ─── 1. التحقق من الصلاحيات وحراس الجلسة ─────────────────────────
require_login();

// ─── 2. جلب البيانات من قاعدة البيانات ───────────────────────────
$stmt = $db->prepare("...");

// ─── 3. تجهيز بيانات العرض ───────────────────────────────────────
```

## 3. العقد الأمني الإلزامي للمطورين (Security Contract)

أي ميزة برمجية جديدة تُضاف للمنصة يجب أن تلتزم بالقواعد الخمس الصارمة:

1. **التعقيم الإلزامي للمخرجات (`e()` Function):**
   - يمنع منعاً باتاً كتابة `echo $_GET[...]` أو `echo $row['title']` مباشرة.
   - يجب دائماً استخدام دالة التعقيم: `<?= e($variable) ?>` لمنع ثغرات XSS.

2. **الاستعلامات المحصنة (Prepared Statements Only):**
   - يمنع دمج المتغيرات في نصوص استعلامات SQL: `query("SELECT ... WHERE id = $id")` مرفوض قطعاً.
   - البديل الإلزامي دائماً: `prepare("... WHERE id = ?")` مع `execute([$id])`.

3. **حماية النماذج ضد التزوير (CSRF Field):**
   - كل نموذج `<form method="POST">` يجب أن يحتوي على الحقل المخفي: `<?= csrf_field() ?>`.
   - كل معالج في `index.php` يمر تلقائياً عبر `csrf_verify()`.

4. **المعالجة المسبقة قبل إخراج القشرة (Pre-Shell Actions):**
   - يمنع إدراج كود معالجة `$_POST` داخل ملفات العرض في `pages/`.
   - جميع معالجات النماذج يجب أن تكون في `index.php` قبل أي إخراج HTML لمنع أخطاء `Headers already sent`.

5. **الرفع الآمن للملفات (`handle_upload()`):**
   - لا تستخدم `move_uploaded_file()` مباشرة في صفحات العرض.
   - استخدم دائماً الدالة المركزية `handle_upload($file, $dir)` التي تفحص نوع الـ MIME، الحجم الأقصى، وتولد اسماً عشوائياً فريداً لمنع التخريب وتجاوز المسارات (Path Traversal).

---

## 4. تصميم النواة والبيانات (Database Design Principles)

1. **الترميز الموحد:**
   - جميع الجداول والنصوص بترميز `utf8mb4` مع `utf8mb4_unicode_ci` لدعم اللغة العربية والرموز الخاصة بشكل كامل دون أي تشويه أو mojibake.
2. **النزاهة المرجعية (Foreign Keys & Cascade):**
   - الجداول المرتبطة بكيانات رئيسية (مثل `campaign_images`, `volunteering_applications`, `notifications`) تستخدم `ON DELETE CASCADE` لضمان عدم بقاء سجلات يتيمة في قاعدة البيانات عند حذف حملة أو مستخدم.
3. **الفهارس (Indexes):**
   - جميع الأعمدة المستخدمة بكثرة في شروط البحث والفلترة (`role`, `wilaya`, `status`, `is_read`, `expires_at`) مفهرسة لضمان سرعة الاستعلامات.

---

## 5. دليل فحص الجودة قبل رفع التحديثات (Pre-Deploy Checklist)

قبل رفع أي تحديث جديد على الخادم أو دفعه إلى Git:
1. **فحص بناء الجملة (Lint Check):**
   قم بتشغيل `php -l` على كل ملف تم تعديله للتأكد من عدم وجود أي خطأ صياغي.
2. **فحص خلو الصفحات من التحذيرات (Clean Output):**
   تأكد من عدم ظهور أي `Warning:` أو `Notice:` في الصفحة أثناء تصفحها.
3. **فحص التوافقية مع الجوال والشاشات المختلفة:**
   تأكد من استقرار شريط التنقل وتناسق الجداول وتجاوب القوائم المنسدلة للبلديات على قياسات الهواتف.
